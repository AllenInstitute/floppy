6. Cross-Cutting Concerns
=========================

Document structural or governance concerns that affect multiple entities
and do not belong in a single field row.

**6.1 Governance, Identity & Multi-Tenancy**

Describe how tenancy, access control, soft-delete, audit trail, and
revision history work in the source system, and confirm they belong in
the Registry platform layer (WS1/WS4), not the portable JSON schema.
Reference the Platform field crosswalk in Section 5 rows tagged
Unmappable.

**6.2 Human Data & HIPAA Considerations**

Document any HIPAA-sensitive fields (date granularity, age capping,
de-identification). Flag date fields that assume full-precision dates
vs. those that require year-only or month/year. Note whether the source
system HIPAA handling has a counterpart in the aind schema.

**6.3 Provenance & Derived Data**

Document how the source system tracks data lineage (raw vs. derived,
source asset references, processing steps). Note gaps relative to aind
data\_description.data\_level, source\_data\[\], and processing.json.

**6.4 Extensibility & Controlled Vocabulary**

Describe the source system approach to controlled vocabulary (e.g.,
per-account dictionaries, free text, external ontologies). Contrast with
the aind approach (vocabulary baked into schema and registries). Flag
fields that require new controlled-vocabulary additions.
