1\. Purpose & Scope

This document applies the BioData Registry schema (aind-data-schema) to
the Patch-seq NHP dataset from the IVSCC program and catalogs every
schema gap, conflict, and unmappable field as required by Milestone 0,
Track C. Patch-seq is a multi-modal single-cell assay that
simultaneously captures electrophysiology, transcriptomics, and
morphology from the same cell, making it a high-value stress test of the
registry schema.

This document was generated using Claude with the source mapping and
info from WS2 Patch-seq\'s mapping exercise.

**A single Patch-seq cell generates four separately stored assets:**

-   NWB file --- intracellular electrophysiology (patch-clamp recording)

-   fastq files --- single-cell RNA sequencing (SMARTer v4 + Nextera
    library prep)

-   Morphological reconstruction --- SWC file + marker file + image
    annotations

-   20x and 63x brightfield/fluorescence images of the patched cell

**Source documents reviewed:**

-   Patch-seq metadata example files: metadata.nd.json (nwb,
    transcriptomics, reconstruction, image 20x/63x)

-   Patch-seq mapping observations.docx (authored by dataset owner)

-   aind-data-schema documentation --- schema\_version 2.7.2

-   BioData Registry kick-off deck and charter (July 23, 2026)

2\. Executive Summary of Key Gaps

The Patch-seq dataset is already formatted in aind-data-schema and
represents the most schema-compliant of the three PoC datasets. However,
several important gaps emerge at the multi-modal, multi-file level: the
schema has no mechanism to group the four modality assets for a single
cell into one logical unit, multi-file and multi-directory location
tracking is not supported, and the majority of Patch-seq-specific
procedures (patch clamping, RNA amplification, library prep, biocytin
filling) fall through to the \"Other\" catch-all type with no dedicated
controlled vocabulary.

6\. Cross-Cutting Concerns

**6.1 Multi-Modal Single-Cell Identity**

The most distinctive structural challenge in Patch-seq is that one
biological unit of interest (a single cell / specimen) generates four
separately registered, independently stored data assets. The schema
provides no way to assert \"these four assets are all from the same
cell.\" Currently, the only link is the shared specimen\_id embedded in
each acquisition and the shared subject\_id in data\_description ---
neither of which is enforced or indexed as a grouping relationship by
the registry. This gap means that cross-modal search (\"find all
Patch-seq data for cells in layer 5 of prefrontal cortex\") requires
reconstructing the cell identity from field values rather than a
first-class relationship.

**6.2 Provenance & Derived Data**

The four modality files have a logical dependency order: the ephys
recording (NWB) is the primary acquisition; the RNA-seq is co-collected
from the same cell; the morphological reconstruction is derived from
images taken post-recording. None of this is captured in
source\_data\[\], which is null in all files. During onboarding, WS3
should populate source\_data linkages to make the derivation chain
explicit and support the registry provenance model.

**6.3 Controlled Vocabulary Coverage**

This dataset reveals that the aind procedure\_type vocabulary was
designed around in-vivo mouse workflows (perfusion, sectioning,
histology). Patch-seq introduces an entirely different set of required
procedure types from molecular biology (nucleated patch extraction, RNA
amplification, library prep) and classical histochemistry (DAB
detection, biocytin filling). These need controlled vocabulary
additions, not free-text workarounds, in order for Patch-seq procedures
to be searchable across datasets.
